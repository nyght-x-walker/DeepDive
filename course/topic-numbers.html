BEYOND THE DEEPDIVE · 2 OF 4

Numbers that do not behave.

In the last chapter we learnt how C++ groups expressions. In this chapter we look at how C++ stores numbers. Integers count exactly. Floating point approximates. That difference explains why 0.1 plus 0.2 is not 0.3, why double equal often fails, and why warnings and sanitizers matter.

PRECISION OF FLOAT AND DOUBLE

Why 0.1 + 0.2 is not 0.3

Float holds about 7 decimal digits. Double holds about 15. Neither can store 0.1 exactly, because it repeats in binary. Move the sliders below to add a and b. The sum shows extra digits you did not type. That is why we never compare floats with double equal. We check the distance against a small epsilon instead.

0.1 + 0.2 = 0.30000000000000004 == fails
if (fabs(a - b) < 1e-9) // close enough, not equal
INTEGERS VS FLOATING POINT

Counting exactly against approximating

Integers count exactly inside their range. Floating point trades exactness for range. Integer division drops the rest, so 7 divided by 2 is 3, not 3.5. Mixing int and double converts the int first, which can surprise you. When you need a fraction, make one side double before you divide.

7 / 2 // 3, int division drops .5
7.0 / 2 // 3.5, double keeps fraction
ERRORS AND WARNINGS

Listen before it breaks

Errors stop the build. Warnings mean the build finished but something looks risky. We compile with Wall, Wextra, and Wpedantic to hear those risks early. Sanitizers go further at run time. AddressSanitizer reports bad reads and writes, like our WRITE of size 16 at offset 40. UndefinedSanitizer reports bad math. We fix warnings before they become overflows.

g++ -Wall -Wextra -Wpedantic main.cpp
g++ -fsanitize=address,undefined main.cpp // reports at run time
