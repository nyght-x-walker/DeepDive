CHAPTER 3 · PHASE 2

When bytes escape.

In the last chapter, we learnt where the line is drawn, where the 8-byte buffer ends and the adjacent memory begins. Now we look at what happens when a byte goes past its storage, when we run a real unchecked copy. In this chapter we use strcpy into char buffer 8 with 15 letters plus the null marker, which makes 16 bytes in total, and we watch the detector report below catch the overflow.

Safety note: the vulnerable pattern here runs only as text and simulation in this course, plus locally compiled demos in an isolated lab. Never deploy it.
THE PROBLEM IN ONE LINE

A copy with no size check

Let's focus on the problem itself. This single line is where everything goes wrong. strcpy takes no size for the destination, so it just keeps copying until it hits the null byte, which is the end marker. It cannot know our buffer holds only 8, so the code on this card shows the full cause.

char buffer[8];   strcpy(buffer, input); // no size, copies to null

WHAT UNDEFINED MEANS

No promises after the overflow

There is one more thing to understand before we leave this chapter. Without the detector, the same overflow may abort or may look perfectly fine, and both outcomes are allowed. Undefined means there are no promises about what happens next, which is why we never trust a run that just seemed to work.
