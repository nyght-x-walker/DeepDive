BEYOND THE DEEPDIVE · 4 OF 4

Data and behaviour.

In the last chapter we learnt what small signs do. In this final breadth chapter we group data and behaviour. Structs hold fields together. Enums name choices. Lambdas hold small behaviour we can pass around. Higher-order functions take that behaviour as input. Together they make patterns like Factory and Singleton.

STRUCTS AND ENUMS

Hold data that belongs together

A struct holds fields that belong together, like id plus a name of 10. An enum names the allowed choices, like direction with north, south, east, west. Both make wrong states harder to write. Our MyData struct from the DeepDive is 14 bytes and can live on stack or heap, same memory you already know.

struct MyData { int id; char name[10]; }; // 14 bytes
enum class Dir { North, South, East, West };
LAMBDAS AND HIGHER-ORDER

Small behaviour you can pass

A lambda is a small function without a name, written where you use it. Brackets hold what it captures. Parentheses hold its inputs. Try the lab below. Change the factor and press Run. The higher-order apply runs your lambda on each item. This is how sort, filter, and transform take behaviour as input.

[3, 6, 9]
auto times = [factor](int x){ return x * factor; }; // capture, input, body
DESIGN PATTERNS

Reused shapes, same pieces

Design patterns are reused shapes built from structs and lambdas. Factory returns the right object while hiding how it is made. Singleton ensures one shared instance. Both rely on what you already learnt. Structs hold the state. Functions and lambdas hold the choice. Smart pointers from Chapter 1 hold the ownership.

Factory
Returns objects, hides construction. Uses structs inside.
Singleton
One shared instance. Uses static plus smart pointer.
