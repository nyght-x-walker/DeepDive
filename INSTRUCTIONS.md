# Project Instructions

Use these rules for all website, handout and code work in this project.

## Voice
* Individual project. Use I, my, me. Do not use we, our, us.
* Write for someone new to the topic. Explain every term the first time it appears.

## Language
* Plain and direct. Short sentences. No filler, no decorative language.
* No em dashes, no triple dashes, no double hyphen separators. Use periods or commas.
* No phrases that refer to the task itself, such as noting that instructions were followed or that content is now interactive. Just show the content.

## Structure
* Start with what the page is about and why it matters.
* List what the reader will know after the section.
* Define key terms with a one line meaning and a concrete analogy.
* Show how parts connect in one simple diagram or sequence.
* Keep handouts and code as styled pages, not raw text files.

## Content
* Cover Stack, Heap, Buffer, Memory, Pointer, Smart Pointer, strcpy, AddressSanitizer and how they relate.
* Show the same numbers everywhere. Buffer 8, input 15, write 16, offset 40, hex 41 to 4F. Keep them consistent.
* Every visualization must teach something. No decorative images.

## Code
* Keep comments short and factual. No meta notes or placeholders.
* Include safety note where code is intentionally vulnerable. Note that it must run only locally.

## Quality
* Text must be readable at 1920 by 1080. No small or clipped text.
* Captions are small and low, not covering the picture.
* Check for 404 before finishing. Every handout and code link must open a styled page.
